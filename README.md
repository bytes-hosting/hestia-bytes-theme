# hestia-bytes-theme

Бічне меню та сучасна тема (світла й темна) для Hestia Control Panel. Ядро Hestia не змінюється.

## Як це працює

| Файл | Куди ставиться | Навіщо |
|---|---|---|
| `src/themes/sidebar*.css` | `web/css/themes/custom/` | Тема у списку «Зовнішній вигляд»; містить лише кольори |
| `src/custom_scripts/hestia-sidebar.php` | `web/js/custom_scripts/` | Завантажувач: Hestia підключає його в `<head>` кожної сторінки |
| `src/custom_scripts/hestia-sidebar/menu.php` | там само | Склад меню |
| `src/custom_scripts/hestia-sidebar/ui.css`, `ui.js` | там само | Вигляд і поведінка |
| `src/custom_scripts/hestia-sidebar/lib.php` | там само | Переклади й правила видимості, спільні для меню та дашборда |
| `src/custom_scripts/hestia-sidebar/dashboard*` | там само | Дашборд: головна сторінка після входу |
| `src/images/*` | `web/images/custom/` | Логотипи та значки вкладки |

Ці папки призначені Hestia для власних доповнень і зберігаються при оновленні.
Меню вмикається лише з темою `sidebar` або `sidebar_*`; з будь-якою іншою темою панель стандартна.
Якщо розмітка Hestia зміниться або меню впаде з помилкою, показується стандартне верхнє меню.

Дашборд відкривається після входу та з логотипа. Він лише читає дані командами Hestia; якщо щось зламається,
користувач потрапляє на стандартну сторінку. Адмін бачить сервер і всі акаунти, користувач — лише свій тариф і домени.

Файловий менеджер (`/fm/`) — окремий застосунок, меню в ньому немає.

## Логотипи

Файли лежать у `src/images/`, усі намальовані одним скриптом: `node dev/logo.mjs`. Правити треба його, а не картинки.

| Файл | Розмір | Де видно |
|---|---|---|
| `logo.svg`, `logo.png` | 100×120 | Сторінка входу; `logo.svg` Hestia бере й для значка вкладки, тому там лише знак без напису |
| `logo-header.svg` | 54×29 | Верхня смуга стандартних тем; у меню, якщо немає `logo-sidebar.svg` |
| `favicon.png` | 64×64 | Значок вкладки |
| `favicon.ico` | 16×16 | Значок вкладки в старих браузерах; спрощений знак |
| `logo-sidebar.svg` | 138×40 | Наше бічне меню; Hestia цього файла не знає |

`install.sh` копіює їх у `web/images/custom/` і запускає `v-update-white-label-logo`: це команда Hestia, яка замінює
стандартні логотипи панелі й повторюється після її оновлень. Якщо в папці є чужі файли, логотипи не чіпаються.
`LOGO=no ./install.sh` ставить аддон без логотипів. `uninstall.sh` повертає ті, що були до встановлення.

## Розробка

Потрібні Docker, Node.js і образ із php-cli 8.2+ та gettext (`PHP_IMAGE`, типово локальний образ Laravel Sail).
Збірки немає: файли з `src/` змінюються наживо, досить оновити сторінку.

```bash
dev/setup.sh
```

```bash
dev/up.sh
```

- http://localhost:8084/?as=admin — адміністратор
- http://localhost:8084/?as=demo — користувач
- `&theme=sidebar|sidebar_dark|dark|default`, `&lang=uk|en`

Працюють справжні шаблони та скрипти Hestia на тестових даних із `dev/fixtures`, служб за ними немає.
`dev/` на сервер не копіюється: `prepend.php` відкриває сесію без пароля.

Розробка з іншою версією Hestia: `HESTIA_REF=<гілка або тег> dev/setup.sh`.

## Перевірка сумісності

Перед оновленням Hestia на сервері:

```bash
dev/check.sh
```

Без аргументів береться останній реліз Hestia. Можна вказати версії чи гілки: `dev/check.sh 1.10.8 main`,
або локальну копію: `HESTIA_SRC=/шлях dev/check.sh`. Код виходу 0 означає, що все пройшло. Одна версія займає близько хвилини;
`VERBOSE=1` показує кожну перевірку.

Що перевіряється:

- усе, на що аддон спирається в коді Hestia: місце вставки меню, функції, поля JSON, іконки, сторінки з меню;
- кожна сторінка `list`, `add`, `edit` під адміном і користувачем відповідає так само, як зі стандартною темою;
- логотипи: файли на місці, меню працює і без них, чужі не перезаписуються, після видалення повертаються попередні;
- права доступу до дашборда, перехід після входу, склад меню;
- збої: файли меню та дашборда ламаються по черзі, користувач має отримати робочу сторінку;
- встановлення (зокрема однією командою), оновлення та видалення на копії Hestia.

Чого не перевіряє: вигляд у браузері, збереження форм, справжні служби сервера, `apt upgrade`.

## Встановлення й оновлення на сервері

На сервері, де Hestia вже встановлено, від root:

```bash
curl -fsSL https://raw.githubusercontent.com/bytes-hosting/hestia-bytes-theme/main/get.sh | bash
```

Команда завантажує останню версію з `main`, ставить меню, дашборд, теми й логотипи та робить `sidebar` темою панелі
за замовчуванням. Користувачі, які обрали собі іншу тему, її збережуть. Та сама команда оновлює вже встановлений
шаблон; тему при цьому не змінює.

Параметри дописуються після `bash -s --`, наприклад `... | bash -s -- --theme sidebar_dark --no-logo`:

| Параметр | Дія |
|---|---|
| `--theme sidebar_dark` | Тема за замовчуванням; `--theme keep` лишає поточну |
| `--no-logo` | Не чіпати логотипи панелі |
| `--ref v1.0.0` | Конкретна гілка, тег або коміт замість `main` |

Якщо завантаження обірвалось або нова версія не проходить перевірку синтаксису, панель лишається як була.

| Дія | Команда |
|---|---|
| Повернути попередню версію | `/opt/hestia-bytes-theme.previous/install.sh` |
| Видалити | `/opt/hestia-bytes-theme/uninstall.sh` |

На сервер потрапляють лише `install.sh`, `uninstall.sh` і `src/`.
